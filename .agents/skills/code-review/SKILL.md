# 代码审查

只读审查：不修改文件、不修测试、不为了让结果变绿调整阈值。

## 基准

先读 `AGENTS.md` 的「二、铁律」与 `docs/python-rules/`，以它们为判断标准；再读 `docs/architecture/` 确认模块边界。

## 重点

- **正确性**：边界条件、空值、异常路径，资源与事务是否成对。
- **铁律**：是否改写了语料源文件、条号是否按数值分量排序、块长口径是否把表格计入、
  `scope` 块与表格「注：」是否被当作答案依据、有无合规结论措辞。
- **契约**：接口改动是否同步 `docs/api/`；失败与降级路径是否符合需求。
- **测试**：新增行为有无对应用例；用例是否只断言措辞。

## 输出

按严重程度排序，每条给出「文件:行号 + 问题 + 触发条件 + 建议方向」。
不提纯风格意见，不复述代码，没发现问题就直说。
