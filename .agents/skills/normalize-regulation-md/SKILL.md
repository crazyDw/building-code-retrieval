# 规范语料标题规范化

把规范 Markdown 的标题标记统一为目标形态，并校验结构完整性。

## 何时使用

向 `数据库上传资料/` 新增或更新规范 `.md` 之后。外部工具的 PDF → Markdown 转换在标题标记上不一致，还可能把条文误标成标题、给目次条目加上标记，这些都会破坏后续的层级解析。

**不适用**：改写正文内容、清理标题内的版式空格、修改表格与公式。这些不在本技能范围内。

## 目标形态

| 对象 | 标记 |
|---|---|
| 章 | `#` |
| 节 | `##` |
| 前言、目次 | `#` |
| 目次条目 | 无标记 |
| 条文（`X.Y.Z` 开头） | 无标记 |

## 工作流

1. **普查**：`python scripts/scan_structure.py <目录或文件>`，输出章/节/条/款/项数量、标记异常、条号缺口。异常为 0 时无需继续。
2. **试运行**：`python scripts/normalize_headings.py <目录或文件>`（默认 dry-run），逐行打印「原行 → 新行」。
3. **核对**：确认改动清单符合预期，重点看"被误标为标题的条文"这一类是否都该改。
4. **落盘**：加 `--apply` 写入。
5. **复验**：重跑 `scan_structure.py`，要求**标记异常 0、条号缺口 0**，且条文总数与改动前一致——改动只涉及标记，不应改变条数。

## 硬约束

- **只改行首标记**，行内其余字符（含行尾空格）原样保留。
- **保持编码与行尾**：UTF-8 无 BOM，沿用原文件的行尾分隔符。
- **逐行断言后再写**：任一行不符合预期即整体中止，不部分写入。
- **不要为了"让文件能入库"而改**：解析器按行首编号形态判断层级，不依赖 `#` 标记数量，因此原始形态也能正确解析。规范化的目的是便于人工阅读与校对，是便利而非前提。
